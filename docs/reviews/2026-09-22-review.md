## 剩余问题与发布边界

1. **P1 / 已确认：统计不是精确一次。** `shorturl-crontab/cron/access_count.go` 先加 MySQL 再减 Redis；两步之间失败会在重试时重复累计。锁 5 分钟无续租，超时任务也可能并行。要完整修复需为批次增加持久化去重凭据和恢复协议，并配套迁移、故障注入验证；本轮没有把这一跨存储设计悄悄改掉。当前 `times` 只适合近似热度，不能用于计费。
2. **P2 / 已确认：创建并非单事务。** `GenerateID → Update` 会留下失败占位行；唯一索引可阻止重复非空映射，但并发冲突仍可能直接返回错误。生产是否已执行仓库中的唯一索引迁移尚未验证。
3. **P2 / 已确认：外部调用取消尚未贯通。** COS 上传、上传后的短链调用及 proxy 使用后台 context；本轮仅完成鉴权超时/取消，未改存储接口和全部 gRPC/数据库调用链。
4. **行为边界：用户短链不等于私密短链。** `/u/:key` 公开跳转，COS/CDN URL 也未做用户校验。这是当前实现，不应对外宣称访问隔离；引入私密分享需要明确产品授权规则。
5. **性能取舍：** 去除错误过滤和无剩余 TTL 的 L1 回填后，冷缓存会增加 Redis/MySQL 访问；每次是单 key/单主键查询，没有全表扫描。生产 QPS、缓存命中率和恶意随机 key 压测未验证。
